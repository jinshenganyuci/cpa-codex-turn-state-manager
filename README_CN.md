# CPA 回合状态管理插件 0.3.3

自动获取、保存和复用 Codex `X-Codex-Turn-State`，**292 优先，332 保底**。安装后直接在管理页面勾选凭据与模型，无需填写插件参数或手动粘贴状态值。

**没有有效 292 / 332 时默认正常放行，后台继续获取。** 获取成功后自动使用缓存；请求不会等待后台获取完成。

## 在 CPA 中安装

适用于支持原生插件 ABI 1 / schema 4 及状态头转发的 CPA 分支。已验证 `jinshenganyuci/CLIProxyAPI` 的 `v7.3.6-codex-identity.1` 和 `v7.3.8-codex-identity.1`。这两个版本无需额外添加请求头映射；不保证任意原版或旧分支兼容。

1. 在 CPA 管理页的配置页面启用插件功能，将下列地址加入「插件源 registry URL」，保存。
2. 打开插件商店，找到「回合状态管理」，点击安装并启用。
3. 打开插件页面「回合状态」，勾选参与获取的凭据和模型，点击「保存勾选」。默认提供 `gpt-6-astra` 和 `gpt-5.6-sol`。

```text
https://raw.githubusercontent.com/jinshenganyuci/cpa-codex-turn-state-manager/main/registry.json
```

这是添加商店来源，不需要合并 `config.example.yaml`。CPA 中需要已有可用的 Codex OAuth 凭据。业务请求使用**凭据自己的代理设置**；插件获取默认沿用该代理，也可在界面启用独立探测代理池。新安装不自动勾选账号或模型；保存勾选后开始自动获取。代理、凭据、密钥及缓存均不包含在发行包中。

插件页面路径：`/v0/resource/plugins/codex-turn-state-manager/status`。默认沿用同站点 CPA 已保存的登录；单独输入管理密钥时，验证成功后由当前浏览器记住。管理接口仍验证密钥。清除浏览器数据、更换域名或登录失效时，需要重新登录。

也可从 [Releases](https://github.com/jinshenganyuci/cpa-codex-turn-state-manager/releases) 下载 Linux amd64 ZIP，将其中的原生库放入 CPA 插件目录，再通过 CPA 页面启用。本仓库仅发布 Linux amd64 安装包，使用 glibc。

## 默认行为

| 项目 | 默认设置 |
| --- | --- |
| 有效值优先级 | 已有值优先 292；获取到有效 292 或 332 均暂停探测，到刷新时间再获取 |
| 无有效缓存 | 原请求正常放行，不返回插件的 503 |
| 后台获取 | 默认每 7 秒重试，可在 UI 自定义；同一组合不叠加任务 |
| 并发 | 不同凭据、模型组合独立；同一组合最多一个进行中的获取任务 |
| 代理 | 业务始终使用凭据代理；插件获取可单独启用代理池 |
| 获取思考强度 | medium |
| 缓存验收 | 完整成功响应、模型一致、结构及时间校验均通过 |
| 刷新 | 默认到期前 30 分钟获取候选值，可在 UI 自定义；最多使用至签发后 60 分钟 |
| 保存 | 自动保存在 CPA 插件目录内的 `.codex-turn-state-manager/` |

重试间隔指同一组合两次获取启动之间的最小间隔，不是请求完成时限。页面每 5 秒刷新状态，不会因此每 5 秒发起探测。慢请求不叠加同一组合；认证、429 和配额错误保留退避。持续获取没有累计次数上限，会消耗对应账号额度。未启用代理池且缺少有效凭据代理时，获取会报告失败；启用代理池但没有可用出口时暂停获取。两种情况都不会自动直连。

手动「探测一次」直接启动；相同组合已经在获取或仍在退避时立即提示，不保存排队任务。「取消正在获取」取消当前任务，之后自动调度仍会继续。要停止某个组合，请取消勾选并保存。

## 探测代理池

在「探测代理池」点击**添加代理**，填名称与完整代理 URL，保存后可点**测试**检查连通性，再点**启用代理池**。支持 SOCKS5、SOCKS5h、HTTP、HTTPS；无需改 CPA YAML。

- **路由分离**：API Key 发起的正常业务请求始终由 CPA 使用对应凭据的代理。代理池只用于插件独立获取 292 / 332，不修改凭据文件或全局代理。
- **管理操作**：支持添加、编辑、删除、启停、测试和解除冷却。修改影响后续获取；已发出的网络请求可以结束，已删除或已换地址的结果不会写入缓存。
- **轮询与并发**：从启用、未冷却的出口中依次选取；不同凭据/模型仍独立并行，同一组合不叠加任务。空池、全部停用或全部冷却时暂停获取，不回退到凭据代理或直连。
- **失败处理**：普通出口连续失败 3 次冷却 60 秒，可在 UI 解除；账号认证和配额错误走凭据退避，不累计出口失败。轮换出口的长度/模型验收失败不触发出口冷却；网络失败仍计入。
- **轮换出口**：只有代理服务本身提供轮换才应勾选。地址可使用 `{session}` 占位符；勾选不会把固定 IP 自动变成轮换服务。
- **测试含义**：发送不带 OAuth 的 HTTPS GET 到上游，只检查连通性，不调用模型，不消耗模型 token。HTTP 401 可以表示成功到达鉴权接口；403 会标明上游拒绝，连通不保证取得有效状态。
- **私密保存**：地址与认证写入独立的 `state_file + .proxies.json`，Unix 文件权限 0600。页面只显示移除认证的地址；编辑地址留空保留原值。设置保存成功后才应用，多窗口冲突会拒绝覆盖。

新安装/升级默认不启用代理池，也不自动导入早期旧池配置。已有代理池设置在重启后恢复。关闭池开关后，插件获取恢复使用凭据自己的代理。

「凭据与模型」和「最近请求」只显示已保存勾选的组合；上方勾选区保留全部凭据，方便增减。未保存的草稿不改变实际范围。

## 获取时间设置

在「获取时间设置」填写两个时间后点击「保存设置」：

- **到期前提前获取**：默认 **30 分钟**，可设 1–59 的整数分钟。例如 20:21 到期，提前 30 分钟即预计 19:51 获取候选值。
- **获取重试间隔**：默认 **7 秒**，可设 1–3600 的整数秒。间隔从同一凭据、模型组合上次获取启动时计算；慢请求不叠加，认证与限额退避仍有效。
- **恢复默认**：保存 30 分钟 / 7 秒，立即生效。

保存后立即重新计算「预计刷新」，重启和升级后保留。已有更新且有效的备用值时，按备用值的到期时间安排下一次获取，避免重复探测。改时间不会清空当前值、备用值或勾选；保存失败不会改变正在使用的设置。

设置自动保存到 `state_file + .schedule.json`，权限 0600。界面保存的值优先于旧 YAML 中的 `probe.refresh_before_seconds`、`probe.retry_seconds`。没有界面设置时才沿用显式 YAML 或新版默认值。页面仍每 5 秒刷新数据，与探测请求的间隔独立。

## 请求出口 IP

最近请求的「请求出口」按两行显示：上方为该次保存的代理名称，下方为出口 IP。探测完成后，插件仅复用该次探测的同一条 TLS 连接读取 `https://chatgpt.com/cdn-cgi/trace`；不为查 IP 重新连接，不携带 OAuth、不额外调用模型。每次新的获取仍独立建立连接，保留轮换出口的行为。

IP 随历史记录保存，代理更名或删除不会改写旧记录的名称。旧记录没有 IP、连接已关闭、查询不可用时显示「IP 未获取」，不拿代理网关地址或另一次查询的 IP 代替。正常 API 请求沿用凭据代理，不增加此查询。

## 缓存、业务观测与模型识别

- 缓存按凭据、账号身份和执行模型隔离。模型与凭据都勾选后才采集、获取和替换；取消勾选会取消对应获取，阻止迟到结果入库，保留已有档案。
- 当前值和备用值都优先 292。合格 292 立即替代当前 332；后来的 332 不覆盖有效 292。同类备用值优先较新签发的值。
- 正常业务完整成功且响应模型一致时，新返回的合格值可以直接入库，来源显示「业务观测」。新的 292 或 332 可以作为备用，减少额外探测。重复值不续期、不改变来源。
- 最近请求分别显示请求模型与实际响应模型。实际响应模型读取上游响应字段，不从长度或回答内容猜测；字段缺失则显示「未提供」。请求别名和执行模型分别记录。
- 明确的模型不一致只失效该请求实际使用的缓存，优先接替有效备用值。已经发出的流式内容不能撤回。无缓存时仍按本版本默认规则放行。
- 凭据显示邮箱及 Pro / Plus / Free / Team 等属性，来自凭据及身份令牌信息，缺失则显示未知；套餐不参与 292 / 332 优先级。

状态值是 opaque 数据，插件只能检查结构与时间，不能验证上游签名。292 / 332 长度、上游报告模型名都不能证明模型能力。跨回合复用属于实验行为；已建立的 WebSocket 连接无法中途修改握手头。

## 保存与升级

默认私密目录跟随 CPA 启动配置中的 `plugins.dir`，不设置时使用工作目录的 `plugins/`。保存当前/备用值、独立勾选文件、最近最多 200 条记录及退避信息。Unix 下文件权限为 `0600`，私密目录为 `0700`；Windows 由保存目录继承的 ACL 控制访问权限。请持久挂载插件目录并确保 CPA 可写；不要公开或提交这些状态文件。

已有明确配置、保存路径及勾选不会被新默认值覆盖。0.3.3 默认提前 30 分钟获取、每 7 秒重试；已有显式时间配置的实例，可以在界面点击“恢复默认”应用新版默认值。**旧版曾显式配置 `block_without_state: true` 的实例，升级时需将其关闭或删除该项，才会采用默认放行。** 本次配套本地实例已关闭。其他用户迁移旧配置时请检查这一项。

`config.example.yaml` 仅供需要自定义模型列表、保存位置或策略的高级用户参考。默认 `force` 表示优先使用有效缓存；`observe` 仅观察，`replace_only` 仅替换传入的 312 长度状态，`dry_run` 记录计划但不改请求。网页模式切换只作用于当前运行，勾选则会持久保存。

旧的 `codex-turn-state` 手动设置插件是另一个项目。不要让两个插件同时修改同一凭据的状态头。0.2.0 以前的 YAML 代理池字段仍只兼容解析并忽略；0.3.0 的新池由界面和独立文件管理。

本版本只在本地构建 Linux amd64 包并上传 GitHub Release；推送标签不会触发自动构建。

## 构建与验证

需要 Go 1.26+、C 编译器及 CGO：

```bash
go test -race ./...
go vet ./...
bash scripts/build.sh
CPA_TEST_BINARY=/path/to/CLIProxyAPI CPA_TEST_PLUGIN="$PWD/dist/codex-turn-state-manager.so" go test -v -count=1 ./integration
```

普通 `go test` 不使用真实凭据，原生集成需要显式传入 CPA 路径。集成测试使用真实 CPA 进程和本地模拟上游，覆盖插件商店安装、无参数初始化、勾选保存、无缓存放行以及缓存值确实到达上游；合成测试值不具备真实上游签名。

历史验证文件分别描述其标题中的旧版本，不代表当前默认设置。0.2.1 的代理与并发验证见 [CREDENTIAL_PROXY_VERIFICATION_CN.md](CREDENTIAL_PROXY_VERIFICATION_CN.md)。源码改编与许可见 [THIRD_PARTY.md](THIRD_PARTY.md)。
