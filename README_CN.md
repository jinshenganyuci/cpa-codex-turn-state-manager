# CPA 回合状态管理插件 0.2.2

自动获取、保存和复用 Codex `X-Codex-Turn-State`，**292 优先，332 保底**。安装后直接在管理页面勾选凭据与模型，无需填写插件参数或手动粘贴状态值。

**没有有效 292 / 332 时默认正常放行，后台继续获取。** 获取成功后自动使用缓存；请求不会等待后台获取完成。

## 在 CPA 中安装

适用于支持原生插件 ABI 1 / schema 4 及状态头转发的 CPA 分支。已验证 `jinshenganyuci/CLIProxyAPI` 的 `v7.3.6-codex-identity.1` 和 `v7.3.8-codex-identity.1`。这两个版本无需额外添加请求头映射；不保证任意原版或旧分支兼容。

1. 在 CPA 管理页的配置页面启用插件功能，将下列地址加入「插件源 registry URL」，保存。
2. 打开插件商店，找到「回合状态管理」，点击安装并启用。
3. 打开插件页面「回合状态」，勾选参与获取的凭据和模型，点击「保存勾选」。默认提供 `gpt-6-astra` 和 `gpt-5.6-sol`。

```text
https://raw.githubusercontent.com/jinshenganyuci/cpa-codex-turn-state-manager/main/registry.json
```

这是添加商店来源，不需要合并 `config.example.yaml`。CPA 中需要已有可用的 Codex OAuth 凭据，并在**该凭据自己的设置中配置代理**。新安装不自动勾选账号或模型；保存勾选后开始自动获取。代理、凭据、密钥及缓存均不包含在发行包中。

插件页面路径：`/v0/resource/plugins/codex-turn-state-manager/status`。默认沿用同站点 CPA 已保存的登录；单独输入管理密钥时，验证成功后由当前浏览器记住。管理接口仍验证密钥。清除浏览器数据、更换域名或登录失效时，需要重新登录。

也可从 [Releases](https://github.com/jinshenganyuci/cpa-codex-turn-state-manager/releases) 下载对应平台 ZIP，将其中的原生库放入 CPA 插件目录，再通过 CPA 页面启用。提供 Linux、Windows、macOS 的 amd64 / arm64 包；Linux 使用 glibc。

## 默认行为

| 项目 | 默认设置 |
| --- | --- |
| 有效值优先级 | 292 优先；只有 332 时先使用，同时继续寻找 292 |
| 无有效缓存 | 原请求正常放行，不返回插件的 503 |
| 后台获取 | 每 5 秒调度检查；普通重试最小间隔 5 秒 |
| 并发 | 不同凭据、模型组合独立；同一组合最多一个进行中的获取任务 |
| 代理 | 每次重新读取对应凭据设置，不使用独立代理池 |
| 获取思考强度 | medium |
| 缓存验收 | 完整成功响应、模型一致、结构及时间校验均通过 |
| 刷新 | 签发后约 55 分钟开始准备替换；最多使用至签发后 60 分钟 |
| 保存 | 自动保存在 CPA 插件目录内的 `.codex-turn-state-manager/` |

5 秒不是保证每次都在 5 秒内完成。慢请求不叠加同一组合；认证、429 和配额错误保留退避。持续获取没有累计次数上限，会消耗对应账号额度。缺少或无效的凭据代理时，获取会报告失败，不改走直连。

手动「探测一次」直接启动；相同组合已经在获取或仍在退避时立即提示，不保存排队任务。「取消正在获取」取消当前任务，之后自动调度仍会继续。要停止某个组合，请取消勾选并保存。

## 缓存、业务观测与模型识别

- 缓存按凭据、账号身份和执行模型隔离。模型与凭据都勾选后才采集、获取和替换；取消勾选会取消对应获取，阻止迟到结果入库，保留已有档案。
- 当前值和备用值都优先 292。合格 292 立即替代当前 332；后来的 332 不覆盖有效 292。同类备用值优先较新签发的值。
- 正常业务完整成功且响应模型一致时，新返回的合格值可以直接入库，来源显示「业务观测」。新的 292 可以作为备用，减少额外探测。重复值不续期、不改变来源。
- 最近请求分别显示请求模型与实际响应模型。实际响应模型读取上游响应字段，不从长度或回答内容猜测；字段缺失则显示「未提供」。请求别名和执行模型分别记录。
- 明确的模型不一致只失效该请求实际使用的缓存，优先接替有效备用值。已经发出的流式内容不能撤回。无缓存时仍按本版本默认规则放行。
- 凭据显示邮箱及 Pro / Plus / Free / Team 等属性，来自凭据及身份令牌信息，缺失则显示未知；套餐不参与 292 / 332 优先级。

状态值是 opaque 数据，插件只能检查结构与时间，不能验证上游签名。292 / 332 长度、上游报告模型名都不能证明模型能力。跨回合复用属于实验行为；已建立的 WebSocket 连接无法中途修改握手头。

## 保存与升级

默认私密目录跟随 CPA 启动配置中的 `plugins.dir`，不设置时使用工作目录的 `plugins/`。保存当前/备用值、独立勾选文件、最近最多 200 条记录及退避信息。Unix 下文件权限为 `0600`，私密目录为 `0700`。请持久挂载插件目录并确保 CPA 可写；不要公开或提交这些状态文件。

已有明确配置、保存路径及勾选不会被新默认值覆盖。**旧版曾显式配置 `block_without_state: true` 的实例，升级时需将其关闭或删除该项，才会采用默认放行。** 本次配套本地实例已关闭。其他用户迁移旧配置时请检查这一项。

`config.example.yaml` 仅供需要自定义模型列表、保存位置或策略的高级用户参考。默认 `force` 表示优先使用有效缓存；`observe` 仅观察，`replace_only` 仅替换传入的 312 长度状态，`dry_run` 记录计划但不改请求。网页模式切换只作用于当前运行，勾选则会持久保存。

旧的 `codex-turn-state` 手动设置插件是另一个项目。不要让两个插件同时修改同一凭据的状态头。旧代理池配置仅兼容解析并忽略，不再影响出口或获取。

## 构建与验证

需要 Go 1.26+、C 编译器及 CGO：

```bash
go test -race ./...
go vet ./...
bash scripts/build.sh
CPA_TEST_BINARY=/path/to/CLIProxyAPI CPA_TEST_PLUGIN="$PWD/dist/codex-turn-state-manager.so" go test -v -count=1 ./integration
```

普通 `go test` 不使用真实凭据，原生集成需要显式传入 CPA 路径。集成测试使用真实 CPA 进程和本地模拟上游，覆盖插件商店安装、无参数初始化、勾选保存、无缓存放行以及缓存值确实到达上游；合成测试值不具备真实上游签名。

历史验证文件分别描述其标题中的旧版本，不代表当前默认设置。0.2.1 的代理与并发验证见 [CREDENTIAL_PROXY_VERIFICATION_CN.md](CREDENTIAL_PROXY_VERIFICATION_CN.md)。源码改编与许可见 [THIRD_PARTY.md](THIRD_PARTY.md)。
